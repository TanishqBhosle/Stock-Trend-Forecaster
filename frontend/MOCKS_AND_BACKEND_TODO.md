# Mocks and Backend Integration Checklist

This document describes which features currently use deterministic mock data and what is needed to replace them with real data sources.

---

## Currently mocked (illustrative demo data)

### Stock data
- **Mock:** `src/mocks/stocks.js` — 11 hardcoded demo tickers with fixed prices, signals
- **Real API endpoint:** `GET /api/v1/stocks`
- **Integration:** Update `fetchStocks()` and `fetchStock()` in `src/services/stockService.js`

### OHLCV historical data
- **Mock:** `src/mocks/ohlcv.js` — 2-year deterministic price series using seeded walk
- **Real API endpoint:** `GET /api/v1/stocks/:ticker?range=1Y`
- **Integration:** Update `fetchOHLCV()` in `stockService.js`

### Forecast results
- **Mock:** `src/mocks/forecasts.js` — illustrative next-day return and signal per ticker
- **Real API endpoint:** `GET /api/v1/forecast/:ticker`
- **Note:** Currently the LSTM is trained only on S&P 500 (^GSPC). Individual stock forecasts require per-stock model training or a different architecture.
- **Integration:** Update `fetchForecast()` in `stockService.js`

### Model evaluation metrics
- **Mock:** `src/mocks/model.js` — `metrics` object has `available: false` and all `null` values
- **Illustrative demo:** `ILLUSTRATIVE_METRICS` is used for visual previews with explicit labels
- **Real artifact:** `models/metrics.json` (generated by running `Stock_Trend_Forecaster.ipynb`)
- **Integration:** Load `metrics.json` into `MODEL_CONFIG.metrics` and set `available: true`

### Prediction history
- **Mock:** `src/mocks/predictions.js` — deterministic 60-day prediction log
- **Real API endpoint:** `GET /api/v1/predictions/:ticker`
- **Integration:** Update `fetchPredictions()` in `stockService.js`

### Backtesting
- **Mock:** `src/services/stockService.js::runBacktest()` — deterministic equity curve
- **Real API endpoint:** `POST /api/v1/backtest`
- **Note:** A real backtesting engine needs historical signal generation from the model. Currently no inference pipeline exists in this deployment.
- **Integration:** Update `runBacktest()` with real API call

### Experiments
- **Mock:** `src/mocks/experiments.js` — 9 illustrative hyperparameter experiment records
- **Real source:** MLflow, Weights & Biases, or a custom experiment tracking log
- **Integration:** Update `fetchExperiments()` / `fetchExperiment()` in `stockService.js`

## Future API surface

The service layer in `src/services/stockService.js` is designed to switch from mock to real by:
1. Setting `VITE_USE_MOCKS=false` in `.env`
2. Setting `VITE_API_BASE_URL=https://your-api.example.com`
3. Implementing each `fetch*` function to call the real endpoints below

### Planned endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/v1/health` | API and model availability check |
| GET | `/api/v1/stocks` | List all available tickers |
| GET | `/api/v1/stocks/:ticker` | Single stock metadata |
| GET | `/api/v1/stocks/:ticker/ohlcv?range=1Y` | Historical OHLCV data |
| GET | `/api/v1/forecast/:ticker` | Next-day forecast result |
| GET | `/api/v1/performance` | Model evaluation metrics |
| GET | `/api/v1/predictions/:ticker` | Historical prediction log |

| GET | `/api/v1/model-card` | Full model card |

## Backend requirements (not yet built)

The project README describes a planned FastAPI backend. When implemented it will need:

- **Model loading:** Load `models/lstm_model.pt`, `models/feature_scaler.pkl`, `models/target_scaler.pkl`
- **Inference endpoint:** Accept a ticker, fetch last 60 days of data, run preprocessing, predict next-day return
- **Historical data:** Yahoo Finance or equivalent live data provider
- **Authentication:** JWT or session-based auth (the frontend currently mocks auth)
- **CORS:** Allow requests from the frontend origin

## Data that is verified (not mocked)

The following information in the frontend is sourced directly from the project README and is accurate:

- Model architecture (2-layer LSTM, 128 hidden units, 60-day lookback, 9 features)
- Feature names and formulas
- Target definition (next-day return, price recovery formula)
- Signal classification thresholds (±0.5%)
- Dataset provenance (Yahoo Finance ^GSPC, 1927–2026)
- Train/Val/Test split ratios (70/15/15)
- Scaler strategy (fit on training data only)
- Sequence creation approach (concatenate-then-slice)
- Known limitations (walk-forward not implemented, volume excluded, etc.)
